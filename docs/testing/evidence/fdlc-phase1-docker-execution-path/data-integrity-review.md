## Controls supported by source inspection

- A hold is written, fsynced, renamed and its parent directory fsynced before `reserve` returns and before fixture I/O. Any failure before return prevents the send. A failure after durable rename can conservatively strand capacity; it does not free it. Atomic lock-directory creation serializes cooperating local processes. A crashed lock is not stolen automatically, favoring safety over availability.
- Request liability uses full admitted input bound plus the requested output cap and integer nano-USD rates. Estimated/unavailable input bounds, unbounded billing dimensions and unproven output enforcement are rejected. Unsafe aggregate arithmetic is rejected. These are fixture assertions, not external proof of provider billing behavior.
- Reservation scope binds workspace, WorkOrder, profile, route, provider, model and price identity; reservation policy digest prevents substituting a different policy. Repeated creation must match the original reservation. Request IDs cannot authorize a second send. Retries require new request IDs and consume the same reservation and total request allowance.
- RESERVED and UNKNOWN retain their maximum liability across reloads. Settlement validates request digest, unique usage ID, safe nonnegative actual liability and the original maximum. Duplicate settlement or duplicate usage is rejected, preserving balances. Usage above the bound leaves the hold unresolved; it is not treated as zero. No automatic path frees unknown outcomes.
- The tests cover wrong scope components, missing/expired reservations, excess payload/output, unproven bounds, pre-send persistence, output-cap forwarding, same-directory contention, unknown/restart, retry consumption, replay, wrong usage linkage, reserved object keys and abandoned locks. Test source was inspected; the reviewer did not execute it. Crash-injection/fsync failure, parseable state corruption and actual distributed authority remain unqualified.
- The Docker image is frozen by ID and checked against inspected image/platform. Allocation preserves lease and manifest metadata for teardown recovery. Recovered providers are marked canceled and cannot resume execution. Resource mutation checks exact container ID, name, provider, lease and manifest labels. A resource name collision is rejected rather than adopted.
- The provider checks invocation manifest digest, Attempt, WorkOrder, source, profile digest and image. The existing supervisor additionally checks manifest causation WorkOrder revision/workflow identity; result validation checks expected Attempt/workflow identities. Allocation workflow database ID and manifest workflow run ID are distinct existing concepts and must not be naively equated.
- The integration test uses a real Factory worker and Docker provider with fixture control-plane responses and a replaced deterministic executor invocation. It does not prove a live Convex claim, independent verifier, actual admitted route, or real Codex model execution. Its failed Attempt is intentional qualification evidence, not pilot acceptance. `fixtureOnly: true`, null provider/inference costs and no acceptance/publication authority correctly preserve this distinction.
- Default routing adds an internal DOCKER provider. No Convex authority schema or migration was observed in the reviewed diff. Widening internal provider/result unions does not by itself establish that live APIs accept or authorize the provider. Existing no-inference profiles now skip credential minting; real inference remains rejected by Docker.
- The ledger persists request digests and usage identifiers rather than raw payloads or credential values. Repository archives are supplied to the container, not mounted from the host. Retention, backup and access governance for a future authoritative ledger remain outside this fixture qualification.
