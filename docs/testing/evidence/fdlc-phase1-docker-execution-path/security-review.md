## Controls supported by inspection

- Docker argv is assembled as an argument array, uses an explicit local Unix socket and pinned image ID, and rejects image-defined volumes. No workload-selected Docker flags, host bind mounts, socket mounts or privileged options are accepted.
- Container creation and subsequent inspection enforce nonroot, read-only root, no network, dropped capabilities, no-new-privileges, private IPC/cgroup namespace, CPU/memory/PID limits, and bounded private tmpfs mounts.
- Docker rejects nonempty credential environments. The runtime now skips credential minting for profiles declaring NONE. The fixed qualification program cannot select a direct provider SDK path; network-none is a separate denial boundary.
- Invocation digest and principal resource identifiers are checked against allocation identity. Existing worker lease/report/publication checks remain in place. Those checks do not replace recovery qualification in SEC-1.
- The fixture ledger persists and fsyncs a hold before calling its fixture, uses atomic mkdir to serialize cooperating processes, denies lock ambiguity and replay, includes unresolved holds in remaining liability, and rejects usage exceeding the hold. The same-directory race test is useful, but does not certify a deployed distributed authority or provider billing.
- The host controller retains powerful Docker daemon authority. It is intentionally outside the workload boundary; this review does not certify resilience against a compromised controller, daemon, base image, or host administrator. Pinned identity is not an image vulnerability scan or provenance attestation.
