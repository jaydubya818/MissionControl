- [x] 2026-08-22 → 2026-09-02 — **Ingress + tool-risk-gate audit (authz slice of the full repository audit)** — audited two guards against their whole input space rather than confirming they exist. (1) `convex/lib/riskClassifier.ts` claimed to be "synced with packages/policy-engine/src/rules.ts" but used a different tool vocabulary; the persona files under `agents/` and `roles/` declare the policy-engine names, so ten tools the policy engine rates RED (`deploy_prod`, `drop_table`, `destructive_shell`, `read_env`, `access_secrets`, `post_social`, `tweet`, `post_linkedin`, `modify_prod_config`, `external_api_write`) fell through to the YELLOW default, which `requiresApproval` auto-allows for SPECIALIST and LEAD. Reproduced (`classifyRisk("deploy_prod") === "YELLOW"`), fixed by adding the RED entries (escalation only), and guarded by a parity test that imports the policy-engine map so the two cannot drift downward again; the false header comment was corrected. (2) `apps/orchestration-server` ingress: `auth.ts` is sound (constant-time compare, fail-closed 503 in production without a token, explicit public-route allowlist), but the `/gateway/ws` upgrade path never passes through it — recorded as an Open design item above rather than patched, because the browser has no credential to present. Along the way the proxy's upstream-close handler was found to read a browser `CloseEvent` shape off the Node `ws` positional `(code, reason)` arguments, so every rejected connect surfaced as `Upstream gateway closed (undefined):`; fixed with a test. Characterization tests were added for `riskClassifier`, `gateway-proxy`, `getActiveTenant` (tenant precedence and the arbitrary-active-tenant fallback for legacy rows) and `sanitize`. Also checked: `packages/research-adapters/src/networkPolicy.ts` (SSRF guard) is already covered by `webRssAdapter.test.ts` and handles IPv4-mapped IPv6, CGNAT, link-local, documentation and multicast ranges with IP pinning across redirects; the only ranges it does not classify as private are NAT64 `64:ff9b::/96` and 6to4 `2002::/16`, which a public DNS answer would not normally carry.

## Governance note for autonomous jobs

This repository's own architectural invariants, as recorded in Jay's design
notes (apple-note p6971), include:

> Humans merge PRs. No full-auto.
> `workOrders.accept` remains the only WorkOrder acceptance authority.
> Executors do not self-certify acceptance.
> Agent completion does not equal verified success.

Automated jobs operating on this repo should therefore open pull requests
rather than merging to `main` directly, even when all checks are green.
