# Factory Engineer package import

## Boundary

Mission Control retrieves a specific immutable Factory Engineer deployment
package through a configured authenticated service channel, then projects the
approved intent into the existing Mission and Plan draft models. The package is
provenance, not Mission Control approval or execution authority.

Import never submits or approves a Plan and never creates a WorkOrder, Task,
Attempt, verification result, release, or deployment. The resulting Mission is
`PLANNING`; its Plan is `DRAFT` and remains editable.

## Wire contract

- Schema: `fdlc.factory-deployment-package/v1`
- Media type: `application/vnd.fdlc.factory-deployment-package+json;version=1`
- Maximum response: 256,000 UTF-8 bytes
- Maximum general contract array: 200 items
- Maximum requested code scopes: 50
- Canonicalization: `fdlc-canonical-json/v1`
- Digest: lowercase SHA-256 over the entire immutable `package` after omitting
  only `package.integrity.digest`
- Canonical JSON: recursively sorted ASCII object keys, compact UTF-8 JSON,
  preserved array order, safe integers only, and no floating-point values
- Identity: configured structured issuer plus `package_id` and
  `package_version`

The cross-repository golden package is
`fixtures/contracts/factory-deployment-package-v1.json`; its adjacent
`.sha256` is generated by Factory Engineer and recomputed byte-for-byte by the
Mission Control test suite.

The immutable package carries status-at-issuance and its exact approval
binding. The mutable attestation repeats issuer, package identity, digest, and
approval; adds current status, publication time, retrieval time, and correlation
ID; and is outside the package digest. Both statuses must be `PUBLISHED`.
Attestations older than the configured bounded freshness window fail closed.

## Authentication and authorization

`factoryPackageImports.preview` and `factoryPackageImports.importDrafts` are
public Convex actions for the browser, but both require a real Clerk identity.
The action calls an internal query that resolves the exact operator and checks
both `delivery.write` and `delivery.assign`. Anonymous/demo identities cannot
use this path.

The target resolver checks an active local project, ready repository, active
owner and team membership, active code scopes in that repository, and an active
local workflow. Confirm re-runs the same checks inside the write transaction.

Factory Engineer location and authority are deployment configuration, not
caller input:

```text
FACTORY_ENGINEER_BASE_URL
FACTORY_ENGINEER_RETRIEVAL_TOKEN
FACTORY_ENGINEER_ISSUER_ID
FACTORY_ENGINEER_ENVIRONMENT
FACTORY_ENGINEER_WORKSPACE_REF
FACTORY_ENGINEER_PROJECT_ID
FACTORY_ENGINEER_RETRIEVAL_TIMEOUT_MS
FACTORY_ENGINEER_ATTESTATION_MAX_AGE_MS
```

The URL must be HTTPS and cannot contain credentials, a query, or a fragment.
The server-held token is sent only in the Authorization header. Factory
Engineer must bind the grant to one engagement, retrieve-only scope, requester
identity/system, expiry, and revocation. Mission Control additionally requires
the package workspace ref to equal `FACTORY_ENGINEER_WORKSPACE_REF` and the
selected local project ID to equal `FACTORY_ENGINEER_PROJECT_ID`; the repository
ref must also equal that project's selected ready GitHub repository. Preview and
the atomic mutation both enforce the local project binding so a same-repository
project in another workspace cannot pass through a stale preview.

The package's `environment_class` is an upstream semantic requirement (for
example, `ISOLATED_NON_PRODUCTION`), not a Mission Control runtime enum. The
operator independently selects `LOCAL`, `CLOUD`, `REMOTE`, or
`POLICY_SELECTED`; Mission Control reauthorizes that selection against its
current code scopes and binds both values in the preview/mapping digest.

Each retrieval has a configured 1–30 second timeout (10 seconds by default)
covering both response headers and the bounded body. Mission Control sends its
operation UUID as `X-Correlation-ID`; Factory Engineer must validate and echo
it in the attestation so the preview, receipt, and both audit trails share one
cross-system correlation value.

## Preview and confirmation

Preview accepts only a package UUID/version and local IDs:

- project, repository, owner member, and owning team;
- one explicit local code-scope mapping for every requested package scope;
- active workflow ID;
- execution environment.

It returns the verified package identity/status, requested and local targets,
Mission/Plan projection, warnings, governance blockers, package digest, and a
mapping digest. It writes nothing.

Confirm takes the same input plus the previewed package and mapping digests. It
re-fetches current attestation and recomputes both digests. A change fails with
`IDEMPOTENCY_CONFLICT` rather than importing unreviewed content or mapping.

The current Plan model binds code scopes at Mission level. V1 therefore
requires every blueprint's `requested_code_scopes` set to equal the package
target set. A narrower or wider blueprint fails with `CODE_SCOPE_REJECTED`
rather than silently broadening execution authority.

Every top-level acceptance criterion must be referenced by at least one
blueprint. Uncovered approved criteria fail validation instead of disappearing
from the Mission Control Plan projection.

## Mapping

| Factory Engineer                                                                                                                                   | Mission Control draft                                                               |
| -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `mission_title`, `objective`, `mission_context`, `intent`, constraint/environment/policy/approval statements, authority ceilings, `stop_condition` | Mission title, objective, context, constraints, stop condition                      |
| authenticated package URL                                                                                                                          | one `URL` source-of-truth reference                                                 |
| local operator selections                                                                                                                          | owner, team, repository, code scopes, execution environment                         |
| `plan_summary`, `specification`, `rollback_approach`                                                                                               | Plan summary and rollback approach                                                  |
| `plan_assertions` plus linked capability, acceptance, and verification refs                                                                        | existing Plan assertions and source-lineage IDs                                     |
| `work_order_blueprints` plus referenced acceptance criteria, requirements, verification requirements, and authority ceilings                       | existing Plan blueprints and constraints with the selected current workflow/version |

Raw customer evidence is not copied. Mission and Plan metadata retain only
issuer/package/version/digest, mapping digest/revision, and correlation ID.
The durable receipt retains minimal approval lineage and requested/local target
bindings.

Factory requirements, agents, skills, tools, models, authority limits, and
verification requirements remain upstream provenance. Mission Control resolves
its current capabilities, policy, implementation policy, independent verifier,
and execution contract before submission/approval. Mutating imported
blueprints therefore remain intentionally incomplete drafts until a human adds
the required branch and implementation policy.

## Governance and idempotency

`missions.plan-release-v1` must be enabled. When
`missions.spec-intake-v1` is enabled, a new imported Mission has no finalized
Mission Spec, so confirm returns `SPEC_INTAKE_REQUIRED` and writes nothing. The
adapter never invents or finalizes a Spec. Preview remains available and shows
both blockers.

The unique external identity is:

```text
issuer_id + package_id + package_version
```

The first confirmed import atomically writes one Mission, one Plan, one owner
assignment, one receipt, and audit events. A concurrent transaction conflict is
retried by Convex against the indexed receipt. The same package digest and
target fingerprint return the original receipt; another digest or target fails
with `IDEMPOTENCY_CONFLICT` and creates nothing.

An identical retry is a read-only receipt return after current authentication
and target validation, so a later feature-flag change does not hide an import
that already completed. Governance blockers are rechecked immediately before
the first write for a new external identity.

## Stable failures

The action returns `{ ok: false, error: { code, message, correlationId } }` for
expected failures. Codes cover authentication/target authorization, unsupported
contract/media, invalid or oversized payload, issuer/approval/digest failure,
not-found/not-published/stale/revoked packages, code-scope/workflow failure,
governance blockers, idempotency conflicts, and bounded temporary failures.
Responses and logs never include the bearer token, response body, or package
content.

For Factory Engineer's shared HTTP `410` withdrawal response, the adapter reads
the already size-bounded JSON and accepts only `PACKAGE_STALE` or
`PACKAGE_REVOKED` from `error.code`; it ignores upstream message text and
correlation data. Unknown withdrawal bodies fail as `INVALID_PACKAGE`.

## Rollout verification

1. Configure the eight server-only values and a dedicated scoped retrieval grant.
2. Keep the UI entry point disabled until a synthetic preview succeeds.
3. Confirm a synthetic package and verify one `factoryPackageImports` row, one
   Mission in `PLANNING`, one Plan in `DRAFT`, and zero WorkOrders.
4. Retry with the same two preview digests and confirm the same Mission/Plan IDs
   return with `created: false`.
5. Change a digest/target, revoke/stale the package, and test another workspace,
   repository, and scope; every case must fail without writes.
6. Monitor `FACTORY_PACKAGE_IMPORTED` Mission events/activities and
   `IDEMPOTENCY_CONFLICT` action results for 24 hours before widening access.
