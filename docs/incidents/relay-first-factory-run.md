## Executive summary

The first Relay run did not establish a trustworthy Objective-to-Acceptance factory path. It did produce useful code and durable evidence, but it also exposed places where Mission Control conflated process completion, verification judgment, and WorkOrder acceptance. The final WO-001 verifier executed against candidate `394414750427c9ea12fe51e46a0b17007691209f`, passed 5 of 9 checks, and ended `COMPLETED / NOT_VERIFIED`. The primary failure was an unusable offline dependency environment that consumed the full 600-second timeout. Later checks were then reported as product failures even though their prerequisite environment had not been established. WO-001 therefore remained blocked and no Relay WorkOrder was accepted.

The Relay run is closed. Its worktrees, candidates, Attempts, verifier mirrors, evidence, and audit records are incident evidence and must remain immutable. Hardening work must target Mission Control; it must not restart Relay or manufacture a passing historical result.

## Classification vocabulary

- **Confirmed bug**: observed behavior contradicts an existing documented invariant.
- **Design gap**: required behavior was absent or ambiguous rather than incorrectly implemented.
- **Environmental failure**: the candidate could not be evaluated because the admitted execution environment was unavailable.
- **Data contamination**: unrelated historical records entered the active run projection.
- **Partial fix**: local code addresses the incident, but the complete invariant or end-to-end proof is not yet present.

## Additional defects found

1. **Resolved locally — verifier prerequisite graph.** Checks now execute through a validated dependency DAG; unknown dependencies and cycles fail closed.
2. **Resolved locally — persisted check vocabulary.** `TIMED_OUT`, `BLOCKED_BY_DEPENDENCY`, and `NOT_EVALUATED` are represented across engine, Convex validation/persistence, and UI projection.
3. **Resolved locally — timeout ownership.** Independent verifier commands now use the same owned process-tree principle as executor commands.
4. **WorkOrder generation is implicit.** Revision and digest guards exist, but a first-class compare-and-swap generation would make stale recovery rejection simpler and auditable.
5. **Factory Run is not yet a first-class membership aggregate for this path.** Project and mission boundaries are too broad for incident-free progress reporting.
6. **Resolved locally — stop and drain semantics.** `drain()` refuses claims and waits; `stop()` interrupts active controllers. Broader per-Attempt cancel UX remains open.
7. **Resolved locally — requirement coverage.** Coverage distinguishes `MISSING` evidence from `NOT_EVALUATED` prerequisites/environment failures.

8. **Factory-injected skills contaminated candidate worktrees.** The Codex worker materialized two factory-owned `SKILL.md` files under `.mission-control/`, excluded them from commit scope, and then rejected its own otherwise-valid candidate as dirty before publication. The worker now removes only those exact factory-owned paths before candidate capture and injects them only for the Codex adapter. Candidate dirty errors now name the exact paths. Fab never receives unused Codex skill files.
9. **Fab erased the cause of contained-check failures.** The adapter converted any internal exception into generic blocked text, while the worker incremented its failure counter without setting `lastError`. It now emits the redacted underlying failure and all explicit terminal failure branches retain an operator-visible reason. This exposed the expected qualification limitation that macOS `sandbox-exec` cannot nest inside the Codex sandbox; those eight native-containment tests are skipped here, not reported as passing.
